# Engineering Intelligence Hub

An AI-powered technical knowledge retrieval system that helps users search engineering documentation and troubleshooting guides using keyword-based, semantic, and hybrid retrieval.

The system combines **TF-IDF, Sentence Transformers, and Reciprocal Rank Fusion (RRF)** to retrieve relevant document chunks through a FastAPI backend and an interactive Streamlit interface.

## Features

- **Document ingestion:** Loads and processes technical documents into searchable chunks.
- **Section-aware chunking:** Preserves document headings and improves the organization of retrieved passages.
- **TF-IDF retrieval:** Finds relevant content using keyword-based similarity.
- **Semantic retrieval:** Uses Sentence Transformers to identify conceptually similar content.
- **Hybrid retrieval:** Combines keyword and semantic rankings using Reciprocal Rank Fusion.
- **REST API:** FastAPI endpoints for health checks and document search.
- **Interactive interface:** Streamlit UI with retrieval-mode selection and configurable result counts.
- **Retrieval evaluation:** Compares TF-IDF, semantic, and hybrid retrieval against a labeled evaluation set.
- **Automated testing:** Pytest tests for core functionality.

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/raviguna901/Engineering-Intelligence-Hub.git
cd Engineering-Intelligence-Hub
```

### 2. Create and activate a virtual environment

On macOS or Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install -r requirements.txt
```

### 4. Process the documents

```bash
python -m src.ingestion.pipeline
```

This loads the raw documents, processes their text, and generates searchable chunks.

## Running the Application

### Streamlit interface

```bash
streamlit run app.py
```

Open the local URL displayed in your terminal, typically:

http://localhost:8501

### FastAPI backend

```bash
uvicorn src.main:app --reload
```

- **API base URL:** http://127.0.0.1:8000
- **Interactive API documentation:** http://127.0.0.1:8000/docs
- **Health check:** http://127.0.0.1:8000/health

## Search Modes

The search API supports three retrieval modes:

| Mode | Description |
|---|---|
| `tfidf` | Keyword-based retrieval using TF-IDF |
| `semantic` | Meaning-based retrieval using sentence embeddings |
| `hybrid` | Combines keyword and semantic rankings using RRF |

Hybrid retrieval is the default mode.

## Running the Evaluation

Run the benchmark comparison:

```bash
python -m src.retrieval.compare_search
```

The evaluation compares all three retrieval methods using the same 20-query evaluation set.

Run the automated tests:

```bash
python -m pytest -q
```

### Latest Evaluation Results

The latest recorded benchmark produced the following results:

| Metric | TF-IDF | Semantic | Hybrid |
|---|---:|---:|---:|
| Top-1 Accuracy | 90% | 90% | 95% |
| Hit Rate@3 | 95% | 100% | 100% |
| Mean Reciprocal Rank (MRR) | 0.9250 | 0.9417 | 0.9750 |

**Metric definitions:**

- **Top-1 Accuracy:** Fraction of queries for which the first result comes from a relevant source.
- **Hit Rate@3:** Fraction of queries with at least one relevant source in the top three results.
- **MRR:** Mean reciprocal rank of the first relevant result.

The benchmark uses source-level relevance labels and a relatively small evaluation set. These results are preliminary and should not be interpreted as proof of general performance on unseen documents or queries. The relevance labels were updated to allow multiple relevant sources for some queries.

## Limitations

- Retrieval quality depends on the document collection, chunking strategy, and evaluation labels.
- Semantic retrieval requires a pretrained sentence-transformer model, which may need to be downloaded on first use.
- The evaluation set currently contains only 20 queries.
- Similarity and ranking scores do not guarantee factual correctness.
- The system retrieves relevant document passages; it does not automatically guarantee a generated answer.
- Performance on this evaluation set may not generalize to other technical domains.

## Future Improvements
